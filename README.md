# kontrol

The web interface to [lok](https://github.com/arkitektio/lok-server), the identity and
configuration server of an [Arkitekt](https://arkitekt.live) hub. It is a React +
TypeScript single-page app with no backend of its own: everything it shows and changes goes
through lok's management GraphQL API and its headless login endpoints.

From kontrol you manage what lok keeps track of:

- **Organizations, memberships, roles and scopes**: who can reach what.
- **Clients**: the apps that authenticate against lok, and the consent screens of its
  OAuth2 / OpenID Connect flows.
- **Services, service instances and hubs**: what an organization runs, and the approval flow
  that lets a service or a hub join.
- **Devices and mesh**: the machines on an organization's private WireGuard mesh.
- **Account security**: social login, TOTP, passkeys and recovery codes.

Signed-out visitors see a single landing page, whose text and links a deployment can
replace without rebuilding. See [LANDING_PAGE_README.md](LANDING_PAGE_README.md).

## How it reaches lok

Kontrol calls lok on its own origin, under `/lok`: `/lok/managementgraphql/` for GraphQL
(`src/Apollo.tsx`) and `/lok/_allauth/browser/v1` for login (`src/lib/allauth.ts`). The paths
are fixed and there is nothing to configure, so one build serves any origin. In return, a
gateway has to put kontrol and lok behind the same host, with lok at `/lok`.

## Development

```sh
pnpm install
pnpm dev         # the Vite dev server on http://localhost:5173
```

The dev server has no proxy to lok. To sign in, serve it behind a gateway that also routes
`/lok` to a running lok.

Other scripts:

```sh
pnpm build       # type-check, build, prerender the landing page, check the chunk graph
pnpm preview     # serve the production build locally
pnpm typecheck
pnpm lint
pnpm lok         # regenerate the GraphQL types and hooks (lok.yml)
```

The GraphQL types and hooks are generated by GraphQL Code Generator from the documents in
`src/graphql`. `pnpm lok` reads lok's management schema from
`https://go.arkitekt.live/lok/managementschema/`, so it needs the network; rerun it after
that schema changes. There is no test suite.

## Releases

Releases are tags: a push to `main` cuts a stable version, a push to `next` a release
candidate. Each one publishes `jhnnsrs/kontrol` under its version (`X.Y.Z`, `X.Y`, `X`), plus
`latest` from `main` and `next` from `next`. The version in `package.json` is a placeholder;
`pyproject.toml` exists only to configure the release tool. Release notes are on
[GitHub Releases](https://github.com/arkitektio/kontrol/releases).
