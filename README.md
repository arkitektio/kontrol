# kontrol

The web interface to [lok](https://github.com/arkitektio/lok-server), the identity and
configuration server of an [Arkitekt](https://arkitekt.live) hub. It is a React +
TypeScript single-page app with no backend of its own: everything it shows and changes goes
through lok's management GraphQL API and its headless login endpoints.

From kontrol you manage what lok keeps track of:

- **Organizations, memberships, roles and scopes**: who can reach what.
- **Clients**: the apps that authenticate against lok, and the consent screens of its
  OAuth2 / OpenID Connect flows.
- **Services, service instances and hubs**: what an organization runs, and the approval flow
  that lets a service or a hub join.
- **Devices and mesh**: the machines on an organization's private WireGuard mesh.
- **Account security**: social login, TOTP, passkeys and recovery codes.

Signed-out visitors see a single landing page, whose text and links a deployment can
replace without rebuilding. See [LANDING_PAGE_README.md](LANDING_PAGE_README.md).

## How it reaches lok

Kontrol calls lok on its own origin, under `/lok`: `/lok/managementgraphql/` for GraphQL
(`src/Apollo.tsx`) and `/lok/_allauth/browser/v1` for login (`src/lib/allauth.ts`). The paths
are fixed and there is nothing to configure, so one build serves any origin. In return, a
gateway has to put kontrol and lok behind the same host, with lok at `/lok`.

## Development

```sh
pnpm install
pnpm dev         # the Vite dev server on http://localhost:5173
```

The dev server has no proxy to lok. To sign in, serve it behind a gateway that also routes
`/lok` to a running lok.

Other scripts:

```sh
pnpm build       # type-check, build, prerender the landing page, check the chunk graph
pnpm preview     # serve the production build locally
pnpm typecheck
pnpm lint
pnpm lok         # regenerate the GraphQL types and hooks (lok.yml)
```

The GraphQL types and hooks are generated by GraphQL Code Generator from the documents in
`src/graphql`. `pnpm lok` reads lok's management schema from
`https://go.arkitekt.live/lok/managementschema/`, so it needs the network; rerun it after
that schema changes. There is no test suite.

## Auth callback relay

Hub services (bank, kuvert, ...) live on the mesh and cannot host the public
redirect URI a third-party login provider requires. Kontrol hosts it for them:

```
https://<kontrol host>/auth/callback/<service>
```

Register that URL at the provider. The page (`src/auth/AuthCallbackRelay.tsx`)
hands the browser back to the desktop app, with the query string unchanged:

```
orkestrator://<service>/auth/callback?code=...&state=...
```

`<service>` is a lowercase slug (`a-z`, `0-9`, `-`); anything else is a 404. The
relay only handles GET redirects, so a provider flow using
`response_mode=form_post` will not work through it.

## Deeplinks and smartlinks

Two share-links that forward a signed-in member of an organization into an app:

```
https://<kontrol host>/deeplink/<org>/<protocol>/<path…>
    ->  <protocol>://<path…>            (query and hash are kept)

https://<kontrol host>/smartlink/<org>/<hub>/<identifier>/<object_id>
    ->  <default protocol>://smart/<org>/<hub>/<identifier>/<object_id>
```

`<org>` is the organization's handle and `<hub>` the numeric hub id. A smartlink
identifier may contain slashes (`@mikro/image`), written literally or as `%2F`.

The link page walks the visitor through whatever is missing:

1. **Log in.** A signed-out visitor is asked to sign up or log in, and returns
   to the link afterwards.
2. **Be a member.** Someone who is not in the link's organization can send a
   request to join; its owner and admins are notified and answer it on the
   organization's overview page ("Requests to join").
3. **Open the app.** The page opens the app and offers its install link for
   people who do not have it yet.

Which apps may be opened is an owner setting on the organization's Settings page
("Link apps"). Each app has a protocol, a name, an https install link and an
"available on mobile" flag. A deeplink must name a registered protocol; a
smartlink opens the first app, or on a phone or tablet the first app available
on mobile. Every organization starts with `orkestrator` (desktop and mobile,
installed from `https://arkitekt.live/docs/use/install`).

The page also says what the link is. What it opens is always described. Where
it leads and who shared it are shown only on opt-in, because the page is public:

- An organization owner can switch on "Show this organization on its links"
  (same card). Anyone holding a link then sees the organization's name,
  description and logo.
- A user can switch on "Show my name and picture on links I share" on their
  profile. A link carrying `?user_id=<their lok user id>` then shows them as the
  person who shared it, but only for an organization that opted in too, and
  only while they are a member of it.

Both are off by default. `user_id`, like the rest of the query, is passed on to
the app.

These checks decide what kontrol forwards. They are not access control for the
target: the app must still authorize whatever the link opens.

## Releases

Releases are tags: a push to `main` cuts a stable version, a push to `next` a release
candidate. Each one publishes `jhnnsrs/kontrol` under its version (`X.Y.Z`, `X.Y`, `X`), plus
`latest` from `main` and `next` from `next`. The version in `package.json` is a placeholder;
`pyproject.toml` exists only to configure the release tool. Release notes are on
[GitHub Releases](https://github.com/arkitektio/kontrol/releases).
